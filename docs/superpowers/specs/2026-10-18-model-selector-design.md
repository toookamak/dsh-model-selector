# DSH 对话框模型快捷切换插件设计

**日期：** 2026-10-18  
**状态：** 用户已确认（2026-10-18）  
**项目：** `F:\Git\dsh-model-selector`（全新空插件工作区）

## 1. 背景与目标

DSH 当前通过列表菜单选择模型。该插件为对话输入框下方提供最多三个可配置的模型快捷按钮，使用户能更快切换常用模型；推理等级作为独立控件，不与快捷模型绑定。原有完整模型菜单继续可用，并始终显示当前模型名称。

目标是交付一个可安装的独立 DSH 插件，不修改 DSH 核心模型选择逻辑，也不增加新的模型或推理服务。为满足指定的控制栏次序，插件可能需要接管模型选择器的显示插槽并重现其菜单界面；模型目录和选择行为仍由 DSH 提供。

## 2. 已确认的交互设计

对话输入框下方的控制栏按如下顺序排列：

1. **最左：推理等级控件。** 使用独立下拉控件，复用当前模型原有的推理等级选项。若当前模型不支持推理等级，则隐藏控件。切换模型不主动修改推理等级；切换模型后，控件依据新模型支持的等级更新。
2. **中间：快捷模型按钮。** 显示零到三个已配置的快捷模型，顺序与设置一致。点击只切换模型，不改变推理等级。若当前模型与其中一个快捷模型相同，该按钮高亮；若当前模型不在快捷列表中，则无快捷按钮高亮。
3. **最右：模型选择菜单。** 在模型选择器显示插槽中重现 DSH 原菜单的全部选择能力，并将菜单按钮标签显示为当前模型名称。通过菜单选择模型后，标签随实际当前模型更新；若该模型属于快捷列表，对应快捷按钮同步高亮。插件接管该插槽的显示组件，但不取代 DSH 的模型目录和模型选择业务逻辑。

插件控制栏随宿主输入区域布局适配；空间不足时可换行，但逻辑次序仍为“推理等级、快捷模型、原有模型菜单”。

## 3. 设置与持久化

- 在 DSH 设置页的插件菜单中提供本插件设置入口。
- 用户可为快捷栏配置最多三个模型；配置顺序决定快捷按钮顺序，未配置的槽位不显示。
- 每个快捷模型可填写可选显示名称。留空时，快捷按钮使用模型原名；填写别名只影响按钮文案，不改变选择目标。
- 同一模型不可重复配置。
- 快捷模型配置不包含推理等级预设；推理等级在对话栏单独切换。
- 配置保存后快捷栏自动更新。
- 配置的模型暂时不在可用模型列表中时，保留配置但隐藏相应快捷按钮；该模型恢复可用后重新显示。

## 4. 组件边界与状态流

插件通过 DSH 支持的对话输入区扩展机制挂载控制栏。由于 `conversation.input.model` 是单组件插槽，若要把菜单放在控制栏最右侧，插件接管该插槽的显示组件并实现菜单界面；模型目录、选择动作与推理等级状态必须复用宿主提供的状态和操作，不修改 DSH 的模型选择业务逻辑。

当前模型和推理等级以 DSH 实际生效状态为准。无论用户通过快捷按钮还是原有菜单完成选择，插件均应依据宿主状态同步模型名称、高亮状态和推理等级选项；切换失败时不得显示虚假的成功状态。

设置保存改变快捷模型列表时，控制栏使用新配置重新渲染。某个模型不可用不会清除用户设置，也不应妨碍其余快捷按钮或原菜单工作。

**当前运行时接口核实记录：** 当前 DSH `0.2.1-rc.2` 的插件包源码和 live Slot tree 已核对：`conversation.input.model` 为单组件插槽且接管有遮蔽宿主 UI 的风险；`conversation.composer.dock` 是 composer 卡片下方的可追加列表插槽；`@deepseek-ai/dsh-client-ui-model-selection` 提供共享 `ModelDirectory`，其 `store`、`load()`、`select(selection)` 可复用；`@deepseek-ai/dsh-client-ui-settings` 的 `configForms` 支持 Host 配置持久化。由于这些包当前未全部挂载，`modelDirectories` 尚未出现在 live Service Inspector；实现时必须在 `dsh.client.inject` 中声明依赖，并在实际加载后再次验证接口与插槽覆盖行为。

## 5. 异常与降级

- 配置有效性在保存时验证：快捷模型不超过三个且不重复；缺少别名时回退到模型原名。
- 暂不可用的配置模型保留但隐藏，其他控件保持可用。
- 模型不支持推理等级时隐藏推理等级控件；支持时展示其原生等级选项。
- 选择动作失败或宿主状态未变化时，仍展示宿主实际状态，不以按钮点击本身推断切换成功。
- 插件重现的模型菜单始终作为选择任意可用模型的回退路径；菜单和快捷按钮均调用 DSH 共享 `ModelDirectory.select(selection)`，目录状态读取 `ModelDirectory.store`，不得另行实现模型目录或核心选择逻辑。

## 6. 验收与测试范围

1. 设置最多能保存三个不同模型；第四个模型或重复模型会被拒绝或阻止保存。
2. 快捷模型显示顺序与设置顺序一致；未配置槽位不显示；别名为空时显示原模型名，填写别名时显示该别名。
3. 点击快捷按钮只切换模型；若切换成功，当前模型按钮高亮且右侧菜单标签显示当前模型名称。
4. 从原菜单切换到快捷列表中的模型时，对应快捷按钮高亮；切换到列表外模型时，右侧菜单显示新模型名且无快捷按钮高亮。
5. 推理等级选项与当前模型的原生选项一致，独立于快捷模型配置；切换模型后按新模型能力更新；模型不支持等级时隐藏控件。
6. 暂不可用模型不显示快捷按钮，但配置保留；其余快捷按钮、推理等级控件（若支持）和原菜单不受影响。
7. 设置保存后快捷栏自动反映新配置；切换失败时 UI 不虚报成功。
8. 在目标 DSH 版本中验证控制栏位置、窄窗口换行、原模型菜单可操作性及快捷按钮与菜单状态一致。

## 7. 非目标

- 修改 DSH 核心模型目录或模型选择业务逻辑；插件仅接管显示插槽以重现菜单界面。
- 为快捷模型保存各自独立的推理等级预设。
- 新增、代理或管理模型服务。
- 显示超过三个快捷模型。

## 8. 设计决策记录

- 选择“扩展输入框现有区域”而非使用浮动面板：它符合用户希望的左/中/右布局。当前 DSH 的 `conversation.input.model` 为单组件插槽，且有替换宿主 UI 的风险；为保留指定布局，插件会接管该显示插槽、重现模型菜单界面，同时继续使用 DSH 的模型目录与选择行为，不修改核心业务逻辑。
- 将推理等级与模型按钮分离：推理等级单独控制并复用每个当前模型的原生选项，避免快捷按钮隐式改变另一项设置。
- 原模型菜单按钮同时承担菜单入口与当前模型状态显示：在模型不属于快捷列表时，用户仍能看到当前所用模型，无需另加状态标签。
- 设置页的快捷模型从宿主已配置的模型目录里选取，而不是手填 Provider ID / Model ID：选项与 composer 菜单同源，保存的 pair 一定有按钮可渲染；已被其它行占用的 pair 在选项层面即不可选，本行自己的 pair 即使目录已不再提供也保留并标注「（不可用）」，可读取、可删除。
- 第 1、2 节里「输入框下方」的位置说明（以及 Plugins 页单入口）已由实施计划的两条修订记录取代：控制行现落在 `conversation.input.model`，即提交按钮左侧的原模型按钮位置；设置入口另有设置面板的「模型选择器」一级页面。控制栏内部的左/中/右次序不变。
